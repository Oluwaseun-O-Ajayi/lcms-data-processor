# Summary

Liquid chromatography coupled to mass spectrometry (LC-MS) separates the components of a sample in time, and the amount of each component is read from the area of its peak in a chromatogram. Turning a chromatogram into numbers involves several decisions: where the baseline lies, where each peak starts and ends, how noisy the signal is, whether peaks are symmetric and separated, and how areas convert to concentrations. LC-MS Data Processor is a Python package that makes each of these decisions explicit. It reads a chromatogram exported as a time-intensity CSV file and returns peak tables, signal-to-noise ratios, asymmetry and resolution checks, calibration curves and plots, using a few hundred lines of documented code.

# Statement of need

Instrument software performs these steps well but hides most of them, so students and early-stage method developers rarely see how a choice of baseline or integration limit changes a reported concentration. Reprocessing exported traces in spreadsheets or one-off scripts is common and error-prone. LC-MS Data Processor gives this audience a small, tested reference implementation: every step can be read in one sitting, its definition is stated in the documentation, and its accuracy is checked against simulated chromatograms whose answers are known. Typical uses are laboratory teaching, comparing processing choices on exported data during method development, and transparent reprocessing for a report or thesis.

# State of the field

Open-source platforms for mass spectrometry, including OpenMS [@Rost2016], MZmine [@Schmid2023] and Skyline [@MacLean2010], process raw instrument data at scale and support feature detection, alignment and targeted quantification. They are the right tools for production analyses, but their size and the breadth of their options make them hard to use for explaining what a single integration step does. LC-MS Data Processor was written as a separate package, rather than as a contribution to these platforms, because its purpose is pedagogical and diagnostic: it works on one exported trace at a time, keeps each algorithm short enough to read, and reports intermediate quantities such as the baseline and integration limits so that users can see and question them.

# Software design

The package is a single module with four classes and a pipeline wrapper. `ChromatogramParser` loads and validates the CSV file. `PeakDetector` estimates the baseline by a morphological opening with a noise-offset correction, refines it in a second pass from the points outside the detected peaks, and estimates the noise as a robust standard deviation of first differences. Peaks are detected on a Savitzky-Golay [@Savitzky1964] smoothed trace with `scipy.signal.find_peaks` [@Virtanen2020], with height and prominence thresholds that never fall below three noise standard deviations. Each peak is integrated by the trapezoidal rule between limits set from its own half-widths at half maximum, so that tailing is followed on the trailing side, and limits never cross the valley between neighbouring peaks. `QualityControl` reports the asymmetry factor at 10% of peak height and the resolution of adjacent peaks from half-height widths, and `CalibrationCurve` fits a least-squares line and predicts unknown concentrations. NumPy [@Harris2020], pandas, SciPy and Matplotlib are the only dependencies.

The design favors transparency over generality. The package reads exported traces only, fits one calibration model, and uses fixed, documented rules instead of tunable deconvolution, so heavily overlapping or strongly tailing peaks are handled less well than by dedicated software.

The test suite checks the processing against simulated chromatograms with known answers (\autoref{fig:accuracy}): recovered areas on a drifting baseline, noise and signal-to-noise estimates, peak widths against Gaussian theory, the resolution of two peaks with a resolution of 1.5, the splitting of overlapping peaks, the asymmetry of symmetric and tailing peaks, and calibration. Continuous integration runs the tests on Linux, macOS and Windows. Writing these tests exposed errors in version 1.0, including an asymmetry factor that always returned values near 1 and a baseline that inflated areas by about 5% at moderate noise; both are corrected and documented in the changelog.

# Research impact statement

The package provides an inspectable, tested reference for the core steps of chromatographic quantification, suited to laboratory courses and to checking processing choices on exported data before they are fixed in a validated method. The bundled synthetic data and accuracy checks make it possible to show students how noise, baseline drift and integration limits affect a reported area. The package has not been validated for regulated or clinical quantification.
